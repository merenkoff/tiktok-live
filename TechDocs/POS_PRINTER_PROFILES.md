# Спільні профілі принтерів

Design doc і точка продовження. Запит власника 2026-11-09, з «Шаблі» (Xprinter XP-58IIH).

## Навіщо

Дешеві 58-мм принтери не нумерують таблиці символів так, як Epson, а частина з них (прошивки для китайського ринку) ще й вмикається в китайському режимі. Касир налаштовує «Кодування кирилиці» на «Обладнанні» пробним аркушем (`PrinterEncodingPicker`, Rust `hardware/encoding.rs`). Якщо один заклад це вже зробив, наступний із таким самим принтером не повинен повторювати: каса сама друкує з перевіреним налаштуванням, доки власник не вибере своє.

## Як це працює

1. **Ключ — драйвер, не ім'я принтера.** `list_printers` (`os_printers.rs`) тепер віддає `driver` — ім'я драйвера в операційній системі (`printers::Printer::driver_name`: Windows «XP-58», macOS «Generic / Text Only»). Ім'я принтера — те, як магазин його назвав («Кухня»), тож для порівняння воно не годиться. Пробіли згортаються однаково на касі й на сервері (`normalizeDriver`).
2. **Звіт.** Коли власник сам вибрав профіль (`printerEncoding:<ім'я>` у налаштуваннях пристрою — об'єкт) і з ним надруковано **3 документи** (чек, передчек, тікет кухні чи квитанція — усе, що йде через `printThrough` у `lib/printer.ts`), каса шле `POST /api/pos/printer-profiles/report { driver, table, esc_t, prints, paper_width_mm }` — один раз на профіль (`printerProfileReport:<ім'я>` на пристрої). Змінений профіль рахується знову; невдалий звіт (немає мережі) повторюється при наступному друку. Затверджений профіль і профіль за замовчуванням не звітуються. Рішення власника 2026-11-09: три чеки, без очікування доби.
3. **Затвердження.** Супер-адмін, вкладка «Принтери» (`/super/printers`, `PrintersPage`): таблиця звітів — драйвер, кодування, **код магазину**, що запропонував, кількість документів, дата — і «Затвердити для всіх» з красивою назвою. Один профіль на драйвер: затвердити інший — замінити (`ON CONFLICT (driver)`). Затверджені можна перейменувати й прибрати; звіти лишаються.
4. **Застосування.** Каса тримає список затверджених (`GET /api/pos/printer-profiles`) у налаштуваннях пристрою (`printerProfiles:shared`), оновлює його у фоні раз на 6 годин і щоразу, коли відкрито «Кодування кирилиці», і без мережі користується збереженим. `loadPrinterEncoding` → `resolvePrinterEncoding`: власний вибір → затверджений для драйвера → за замовчуванням (Windows-1251 · 46). Рядок на «Обладнанні» каже «… — налаштування LiveShop для «Xprinter XP-58IIH»»; власник може вибрати своє, а потім «Використати налаштування LiveShop» (власний вибір стирається — `null`).

## Сервер

Міграція `100_pos_printer_profiles.sql`: `pos_printer_profile_reports` (один рядок на магазин + драйвер + таблиця + номер; повтор лише піднімає `prints` і дату) і `pos_printer_profiles` (UNIQUE `driver`, `title`, `source_store_id` SET NULL). `esc_t` завжди — номер, який профіль справді вибирає (стандартний підставляється), тож «CP866 без номера» і «CP866 · 17» — один профіль. Сервіс `src/pos/printer-profiles.service.ts`; маршрути каси — core-група `routes/printer-profiles.routes.ts` (`ensurePosAuth`, маркетолог — 403 за замовчуванням); супер-адмін — `GET /super/printer-profiles`, `POST /super/printer-profiles/reports/:id/approve`, `DELETE /super/printer-profiles/reports/:id`, `PATCH`/`DELETE /super/printer-profiles/:id`.

## Платформа й релізи

`PLATFORM_VERSION` не змінюється: усе в хості (`lib/printer.ts`, `lib/printerProfiles.ts`, `PrinterEncodingPicker`), у Rust і на сервері; `PrinterInfo.driver` — необов'язкове поле типу. Іде з POS Release 2.9.1 разом із `FS .` (вихід із китайського режиму). Сервер деплоїться першим; каса старіша за 2.9.1 нічого не звітує й не отримує, а каса 2.9.1 зі старим сервером тихо мовчить (усі виклики ковтають помилки).

## Чого немає

- Затвердження «автоматом» — лише руками супер-адміна: дешеві принтери різних марок часто ставляться з одним драйвером «POS-58».
- Ширини паперу в спільному профілі: вона приходить у звіті для довідки, але не застосовується.
- Профілю для веб-каси й планшета: вони друкують через браузер, без ESC/POS.
