## 1. Навіщо

Раунд іде на кухню цілим, а виносять його частинами: борщ зараз, вареники за
десять хвилин, і несе той, хто вільний. До `115` стан мав лише **раунд**
(`pos_bill_rounds.prep_status`: `new → ready → served`, міграція 052), тож
«борщ винесли, вареники ні» не було де записати. А рядок рахунку зливається:
один рядок може бути «3× Борщ».

## 2. Рішення власника (2026-11-24)

- **Д1.** Назва «Роздача», id модуля `pass`, порт 5013.
- **Д2.** Екран — варіант власника з доробками (варіант A):
  - угорі горизонтальна стрічка столів, у яких є відкритий рахунок; перша плашка «Усі», на кожній — скільки страв ще винести;
  - нижче раунди з невинесеними стравами — спершу вибраного столу, далі «Інші столи»;
  - ще нижче «Винесено» — увесь уже винесений чек вибраного столу, хто й коли, «Повернути», поки можна;
  - тап по страві → лист «Несете на стіл 5?» з кнопками «Несу» / «Ні»; для ×N — вибір кількості (за замовчуванням «Усі N»);
  - після «Несу» страва зникає, і 5 секунд висить «Борщ ×1 винесено · Повернути».

  Питання «Несете?» — бо тапають на роздачі, коли тарілка ще в руках: відмітка
  одразу каже іншим офіціантам, що цю тарілку вже взяли.
- **Д3.** «Готово» на кожній страві від кухні (двоступенева схема, як у Toast)
  — **пізніше, окремим етапом**.
- **Д4.** Тап по вільному столу питає «Скільки гостей?» з «Пізніше» — це фаза A.

Відкинутий варіант B: тап лише ставить галочку, одна кнопка «Несу 3 страви» внизу
відмічає все разом, без питання. API приймає кілька рядків в одному запиті, тож
повернутися до нього можна без зміни сервера.

## 4. Модель даних (міграція `115`)

`pos_bill_item_serves` — один рядок на один акт «виніс»:

| поле | що |
|---|---|
| `bill_id`, `round_id`, `bill_item_id` | що винесли |
| `quantity` | скільки (> 0) |
| `source` | `waiter` — тап у «Роздачі»; `kitchen` — решта раунду, яку кухня видала своїм «Видано» |
| `served_by`, `served_at` | хто й коли |
| `client_uuid` | один на запит (тацю); повтор після тайм-ауту повертає ті самі рядки |
| `undone_at`, `undone_by` | «Повернути»: рядок більше не рахується, але лишається |

**Рядки — єдина правда.** Скільки винесено = сума живих рядків
(`servedQuantitySql`, `src/pos/served.ts`), колонки поряд немає:
- відправлений рядок не змінюється, тож сума не може розійтися з кількістю;
- «Повернути» — це прапорець, а не друге число, яке треба тримати в такт.

**Раунди, видані до `115`,** рядків не мають. Раунд `served` читається як
винесений цілком, тож нічого не заповнюється заднім числом і автор не
вигадується.

**Інваріанти** (перевіряє `pos.serving.test.ts`):
- I1 — винесено ≤ кількості;
- I2 — у раунду не в `served` є що виносити;
- I3 — `served`-раунд із рядками винесено цілком.

## 5. Правила, які легко зробити навпаки

1. **Офіціант виносить і з раунду, який кухня ще не назвала «Готово».**
   - Страви йдуть з роздачі по одній задовго до того, як готовий увесь раунд.
   - Коли виносять ОСТАННЮ тарілку, раунд сам стає `served`, а `ready_at`
     лишається як був: «Повернути» мусить знати, чи кухня взагалі казала «Готово».
2. **«Видано» кухні на частково винесеному раунді виносить решту** рядками
   `kitchen`. «Винесено» показує кожну тарілку, а сума лишається однією правдою.
   «Видано» з `new` і далі відмовляє словами кухні («Спершу натисніть „Готово“»),
   повторне «Видано» — 200 без нових рядків.
3. **Порядок блокувань у всіх, хто пише:** рахунок → раунд → рядки, за id.
   - Той самий порядок у `fireRoundTx`, `cancelRound` (з фази A) і в записах самого рахунку.
   - Блокування раунду дає «двох офіціантів і один останній борщ»: одному 200,
     другому 409 `over_served` з іменем — «„Чай“ уже винесено — Оля о 19:42».
4. **Оплачений рахунок тап приймає.** Оплата йде наввипередки з виносом увесь
   вечір (гість платить, поки десерт у дорозі). Скасований рахунок або раунд —
   відмова: `bill_cancelled` / `round_cancelled`.
5. **Таця — усе або нічого**, навіть через два столи; чернетка —
   `line_not_fired`, чужий магазин — 404.
6. **«Повернути» — для помилки, а не для повернення:**
   - 10 хвилин (`UNDO_MINUTES`);
   - свій тап або власник (`undo_not_yours`);
   - ніколи не рядки кухні (`undo_kitchen`) і ніколи після того, як кухня видала
     решту цього раунду (`undo_after_kitchen`);
   - раунд, який закрив скасований тап, повертається туди, де його лишила кухня:
     `ready`, якщо вона казала «Готово», інакше `new`.
7. **`cancelRound` відмовляє раунду, з якого вже винесли:** «З раунду вже винесли
   страви — скасувати його не можна». Зварене й з'їдене на полицю не
   повертається, поки тап не повернули.
8. **«Роздача» без «Столів» не підключається:**
   - `MODULE_REQUIRES` / `assertRequiredRemotes` у `src/pos/core/modules.ts`;
   - 400 з `PATCH /store` і з супер-адмінки;
   - віддалений модуль сам цього сказати не може — `requires` у його дескрипторі відкидається.

## 6. API (`src/pos/routes/serving.routes.ts`, core-група, `ensurePosAuth`)

| маршрут | що |
|---|---|
| `GET /serving` | `{ now, tables[] }`: кожен відкритий рахунок (стіл, зал, `to_serve`) з живими раундами і рядками (`quantity`, `served_quantity`, `caption`, `note`, `modifiers`, `stations`) |
| `GET /serving/bills/:id` | ті самі раунди + `history[]` (новіші вгорі, до 100): хто, коли, `source`, `undoable`, `undo_until` |
| `POST /serving/serve` | `{ client_uuid, items: [{ bill_item_id, quantity }] }` (1–50, той самий рядок двічі — сума) → `{ replay, events, lines, rounds }` |
| `POST /serving/undo` | `{ event_ids }` → `{ undone, lines, rounds }`; уже повернуті пропускаються |

Відмови — `{ error, code, …detail }`, `error` — речення для офіціанта:
- 400 — поганий ключ або перелік;
- 404 — «Страву не знайдено»;
- 409 `over_served` / `line_not_fired` / `round_cancelled` / `bill_cancelled` / `undo_*`.

Інші зміни на сервері:
- `GET /kitchen/orders` дає `served_quantity` рядкам раунду, `getBill` — відправленим рядкам. Поле нове, старі модулі його не читають.
- Розділ каси `pass` закриває всі чотири маршрути (`SECTION_ROUTES`).
- Маркетолог відхилений за замовчуванням.

Викатка B1 — лише деплой API, старі екрани працюють як раніше. Наслідки:
- кухонне «Видано» тепер пише рядки `kitchen`;
- раунд, з якого вже винесли, не скасувати.
