# Первое включение фіскалізації (Cashalot) для магазина

Пошаговая инструкция для оператора/владельца — вторая после
[Checkbox](../checkbox/POS_FISCAL_CHECKBOX_SETUP.md), той же структуры.
Контекст и архитектура — [POS_FISCAL_PRRO.md](../POS_FISCAL_PRRO.md); дизайн
провайдера и точка возобновления трека — [POS_FISCAL_CASHALOT.md](POS_FISCAL_CASHALOT.md).

> **Статус (2026-10-27).** Адаптер (CA5) и бандл (CA6) написаны и прогнаны
> **только против заглушки** (`src/__tests__/helpers/fake-cashalot-server.ts`
> и e2e `pos/e2e/fiscal-cashalot.spec.ts`): ключей Cashalot у нас ещё нет
> (CA0). Экраны и подписи здесь — настоящие, из кода; что ответит живой ПРРО
> на каждом шаге (форма дубля, тестовый документ в кабинете, `Available`) —
> покажут пробы CA3. После них сверить разделы 1, 6 и «Диагностика».

Чем Cashalot для владельца отличается от Checkbox — одним абзацем:
**сессии нет** (три значения из кабинета в каждом запросе), **таблицу ставок
вводит владелец** (Cashalot её не отдаёт), **тестовый режим — переключатель
у нас** (песочницы у Cashalot нет, тестовые чеки идут на настоящий ПРРО с
отметкой `TESTING`), **офлайн-режима нет** (раздел 7), **чек всегда наш**
(провайдер верстает только картинку).

## 0. Проверить один раз перед первым магазином

### 0.1 `POS_SECRETS_KEY` задан в проде

То же, что у Checkbox, п. 0.1: без него сохранение ключей отвечает 503 —
на экране «Фіскалізація — Cashalot» это красная карточка
«POS_SECRETS_KEY is not configured» с кодом `FC-SRV503-…`. Проверить на
Railway (сервис API → Variables); сгенерировать:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```
и **записать помимо Railway** — без ключа сохранённые креды не прочитать.

### 0.2 Бэкенд с миграцией `072`

`072_pos_fiscal_receipts_provider_offline.sql` (режим `provider_offline` —
чек, который Cashalot зарегистрировал в своей офлайн-сессии) накатывается
при старте контейнера, как и все. Проверить:
```bash
psql "$DATABASE_URL" -c "select conname from pg_constraint where conname like 'pos_fiscal_receipts_mode%';"
```

### 0.3 Из прода Cashalot доступен

Разработка Cashalot предупреждала, что IP из стран под ограничениями могут
блокироваться. Проверено 2026-10-27 из контейнера API на Railway (EU West):
`ServerState` отвечает `200` за ~0,2 с — как с машины разработчика
(`src/__tests__/fixtures/cashalot/README.md`, находка 1). Если регион
сервиса сменится — повторить одной командой оттуда же (команда в том README).
Сам ФСКО (`fs.tax.gov.ua`) оттуда тоже отвечает (1.11.2026, 85 мс) — это
важно только для FS API на своём сервере (раздел 7).

## 1. Кабинет Cashalot: что нужно получить

Кабинет — `https://my.cashalot.org.ua` (первый месяц бесплатно; дальше
модуль «КАСА» — 200 грн/мес при годовой оплате за одну кассу — цены с
сайта на 2026-10-21, `sources/integration-facts.md`). В нём, по порядку
(спека WEB API, разд. «Початок роботи»):

1. **Господарська одиниця** и **каса (ПРРО)**, зарегистрированные в ДПС
   (20-ОПП, 1-ПРРО) — как для магазина на Checkbox. В форме **1-ПРРО
   разрешить работу в офлайн-режиме**: при сбое ФСКО (такой был 27.10.2026)
   Cashalot регистрирует чеки в своей офлайн-сессии только для касс с этим
   разрешением, остальным — отказ до восстановления связи ДПС (ответ
   разработки 15–16, `sources/support-answers.md`).
2. **Касир** (5-ПРРО) с КЕП; в списке касс — «завантажити і зберегти
   ліцензії для ПРРО». Без этого шага каждая команда с ключами отвечает
   `LicenseViolation` «Відсутня ліцензія на ПРРО з фіскальним номером …» —
   первое, на что мы наткнулись 1.11.2026.
3. **Налаштування → Інтеграція з WEB API** — включить; в
   **Управління касирами** появятся два значения, которые просит наша форма:
   - **Ідентифікатор ключа (KeyGuid)**
   - **PIN касира**
   
   Ключ КЕП при этом остаётся у Cashalot — файлы ключей нам не нужны.
4. **Фіскальний номер ПРРО** (ФН) — на странице кассы (Каси → обраний ПРРО).
5. **Таблица ставок налога** — буквы и названия так, как они заведены в
   кабинете (раздел налоговых ставок; точный путь в кабинете — сверить после
   CA0). Разработка советует брать именно их:
   если касса уже работала, те же `NAME` и `LETTERS`, что и раньше. Буквы —
   **только кириллицей** (А, Б, В…). ФОП без ПДВ — таблица пустая, чек идёт
   без букв.

Отдельной демо-кассы Cashalot не даёт: первые чеки пробиваются на настоящий
ПРРО в **тестовом режиме** (раздел 5), где каждый документ помечен
`TESTING` и не имеет фискальной силы.

## 2. Выпустить бандл `fiscal-cashalot` (если ещё не выпущен под текущую версию)

Проверить, есть ли релиз под текущую версию `pos/package.json`:
```bash
git tag -l "module-fiscal-cashalot-v*"
```
Если нужного тега нет:
```bash
gh workflow run module-release.yml -f module=fiscal-cashalot
```
(или GitHub → Actions → «Module Release» → Run workflow → `module` =
`fiscal-cashalot`). Воркфлоу берёт версию из `pos/package.json`, собирает,
подписывает **прод-ключом** (джоб упадёт, если подписалось dev-ключом),
гоняет `check:fiscal-cashalot-css-coverage` и публикует на `module-builds`.
Проверить (~1–2 минуты):
```bash
gh run list --workflow=module-release.yml --limit 3
```
URL бандла после успеха:
```
https://cdn.jsdelivr.net/gh/merenkoff/tiktok-live@module-fiscal-cashalot-v<версия>/fiscal-cashalot/remote-entry.js
```
(версия — из `pos/package.json`). **Этот шаг ничего не меняет ни для одного
магазина** — просто кладёт файл на CDN. Подключение — шаги 3–5.

## 3. Владелец: провайдер в карточке

`/admin` → Налаштування → «Фіскалізація (ПРРО)»:

1. **Провайдер** → «Cashalot». Если до этого стоял Checkbox с сохранёнными
   ключами, карточка спросит подтверждения: сервер стирает креды прежнего
   провайдера вместе с ним.
2. **«Зберегти ПРРО»**. «Реєструвати чеки в ПРРО» пока не включать —
   сначала шаги 4–5.

Чего на карточке **нет** для Cashalot, и это не поломка: «Джерело чека» и
«Ширина чекової стрічки» — Cashalot отдаёт чек только картинкой, поэтому
касса всегда печатает наш макет с фискальным блоком. «Код ставки за
замовчуванням» здесь не трогать: для Cashalot он выбирается из таблицы ставок
на экране бандла (шаг 5), и карточка об этом пишет под полем.

## 4. Подключить модуль `fiscal-cashalot`

Налаштування → «Онлайн-модулі» → «+ Додати модуль»:
- **Ідентифікатор**: `fiscal-cashalot`
- **Джерело (URL remote-entry.js)**: ссылка из шага 2
- нажать «+ Додати модуль» **ещё раз** (форма двухступенчатая — та же
  ловушка, что у Checkbox, п. 4), убедиться, что запись в списке, и нажать
  общую **«Зберегти»**.

Сервер откажет в двух случаях, и оба — намеренно: в `module_remotes` может
быть **один** модуль `fiscal-*`, и его провайдер должен совпадать с выбранным
на карточке (`assertSingleFiscalRemote`). Поэтому магазин, переходящий с
Checkbox, сначала убирает `fiscal-checkbox` из списка, потом добавляет
`fiscal-cashalot` — и шаг 3 должен быть сделан раньше шага 4. Кассиру и
владельцу нужно перезайти, чтобы модуль подгрузился.

## 5. Экран «Фіскалізація — Cashalot» (`/admin/fiscal`)

1. **Дані доступу** — три поля из раздела 1: «Ідентифікатор ключа (KeyGuid)»,
   «PIN касира», «Фіскальний номер ПРРО» → «Зберегти дані доступу». Под
   каждым появится «Значення збережено»; значения назад не показываются.
2. **Ставки податку й режим** — «+ Додати ставку» на каждую ставку из
   кабинета: літера, назва, відсоток; у одной отметить «За замовч.» — её
   буква пойдёт на каждую строку чека. Поставить **«Тестовий режим»**.
   «Зберегти ставки й режим» — таблица, режим и ставка по умолчанию уходят
   одним сохранением. Сервер проверяет таблицу сам и отвечает своими словами
   («Ставка 2: літера має бути однією кириличною…», «…лише при закритій
   зміні…»).
3. **«Перевірити з'єднання»** — ожидаемо «З'єднання успішне · Каса: ПРРО
   <ФН> · Ліцензія до <дата>». Имя касира появится, когда будет открыта
   зміна. Если ошибка — «Диагностика» ниже, **дальше не идти**. Успешная
   проверка заодно кладёт в кэш «Реквізити ПРРО» (организация, ЄДРПОУ/ІПН,
   точка, адрес, ФН и таблица ставок из п. 2) — они печатаются в шапке чека.
4. Вернуться в карточку «Фіскалізація (ПРРО)» → включить **«Реєструвати чеки
   в ПРРО»** (чекбокс активен, когда провайдер выбран и адаптер есть),
   «Відкривати зміну автоматично» — по желанию → «Зберегти ПРРО».

Над экраном при включённом тестовом режиме висит плашка «Тестовий режим.
Чеки реєструються як тестові, без фіскальної сили» — это ожидаемо до раздела 6.

## 6. Первый чек — тестовый, потом настоящий

1. На кассе `/fiscal` («Зміна») — плашка «Тестова зміна — чеки без
   фіскальної сили» → «Відкрити зміну». Зміна откроется в Cashalot как
   тестовая (`TESTING`).
2. Пробить одну продажу на минимальную сумму. На экране успеха —
   «Фіскальний чек № <номер> зареєстровано»; в «Чеках» у продажи зелёный
   бейдж ПРРО; на чеке — «ФІСКАЛЬНИЙ ЧЕК · ПРРО Cashalot», «ПДВ <літера>
   <ставка>%» с суммой, которую зарегистрировал Cashalot, «ЧЕК №», «ФН ПРРО»
   и QR. Проверить в кабинете Cashalot, что документ есть и помечен
   тестовым (как именно — сверить после CA3).
3. Закрыть зміну («Закрити зміну» на `/fiscal` или дождаться крона).
4. На `/admin/fiscal` снять **«Тестовий режим»** → «Зберегти ставки й режим».
   Сервер разрешит это только при **закрытой зміні** и **пустой очереди**
   чеков (иначе ответит «…лише при закритій зміні…» или «Є чеки, що ще
   реєструються в ПРРО…» — повтор отправки шлёт сохранённый чек под текущим
   режимом, и тестовая продажа ушла бы фискальной).
5. Открыть зміну заново, пробить первый **фискальный** чек, проверить его по
   QR на сайте ДПС и в кабинете. С этого момента — обычная работа: закрывать
   зміну вечером или доверить крону (не позже 23,5 ч после открытия).

Режим зміни и режим кассы должны совпадать: если зміну открыли в кабинете
Cashalot в другом режиме, чем стоит у нас, касса откажет словами «Відкрита
зміна тестова, а каса налаштована як фіскальна — закрийте зміну в кабінеті
Cashalot» (или наоборот).

## 7. Чем Cashalot отличается для владельца

- **Офлайн-режима у нас нет** — переключатель «Офлайн-режим ПРРО» в карточке
  не показывается. Облачный WEB API Cashalot сам работает с ДПС в своей
  офлайн-сессии, пока доступен его сервер: такой чек приходит сразу с
  номером и QR, печатается с отметкой «ОФЛАЙН» и в «Чеках» виден как
  «ПРРО: офлайн». Касса **без интернета** на Cashalot не продаёт
  (ограничение облачного API; подробнее — [POS_FISCAL_CASHALOT.md](POS_FISCAL_CASHALOT.md), фаза CA8).
- **Первый вызов ПРРО обязан быть онлайн** — это требование самого Cashalot.
- **Буквы ставок не менять в открытой зміні** и не давать одну букву двум
  налогам — сервер и не даст.
- **Одна каса — одно устройство** одновременно: Cashalot хранит состояние
  ПРРО у себя, и две кассы на одном ФН расходятся
  (`InconsistentRegistrarState`, см. «Диагностика»).
- ПДВ на чеке — тот, что зарегистрирован (`CHECKTAX` считаем мы по правилам
  ДПС), а не пересчёт кассы.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «POS_SECRETS_KEY is not configured», код `FC-SRV503-…` | Ключ не задан в проде | П. 0.1 |
| «Для провайдера «Cashalot» у цій версії застосунку немає модуля» | Деплой бэкенда старше CA5 | Обновить деплой API на Railway |
| «Для Cashalot потрібні ідентифікатор ключа, PIN касира і фіскальний номер ПРРО» | Не все три поля сохранены | П. 5.1 |
| `LicenseViolation` «Відсутня ліцензія на ПРРО з фіскальним номером …» | На кассу в кабинете не загружена лицензия | Кабинет → Каси → обраний ПРРО → завантажити ліцензію (п. 1.2), повторить проверку |
| «Відсутній доступ до ПРРО для користувача» / ошибка авторизації при проверке связи | Неверные KeyGuid/PIN, интеграция с WEB API выключена в кабинете, или ФН не этой кассы | Перепроверить в кабинете: Інтеграція з WEB API → Управління касирами, Каси |
| «Відкрита зміна тестова, а каса налаштована як фіскальна…» (или наоборот) | Зміна открыта в кабинете в другом режиме, чем у нас | Закрыть зміну в кабинете Cashalot, открыть с кассы |
| `DocumentValidationError` «…ознаки тестового … не дорівнює значенню ознаки зміни» | Чек в режиме, не совпадающем со зміною | То же: закрыть зміну, сверить «Тестовий режим» |
| «Рядок «…» без ставки податку» / «ставки «X» немає в таблиці податків ПРРО» | «Код ставки за замовчуванням» не из таблицы (вписан на карточке руками, или таблицу переписали) | На `/admin/fiscal` отметить ставку «за замовч.» и сохранить |
| «Ставки податку й тестовий режим змінюються лише при закритій зміні» | Зміна открыта | Закрыть зміну, сохранить снова |
| «Є чеки, що ще реєструються в ПРРО, — дочекайтеся їх…» | В очереди повтора есть чеки | Подождать крон повтора (2 мин) или разобрать «Потребують уваги» |
| Чек с `providerCode` `InconsistentRegistrarState` / `CheckLocalNumberInvalid` в «Потребують уваги» | Состояние ПРРО в Cashalot разошлось с ДПС (чаще — вторая касса на том же ФН) | Команда **Cleanup** WEB API для этой кассы (спека, разд. «Приведення локального стану ПРРО…»; есть ли кнопка в кабинете — сверить после CA0) — стирает неотправленные офлайн-документы и закрывает зміну; затем повторить |
| Чеки идут «ПРРО: офлайн» (`provider_offline`) | У ДПС сбой ФСКО (`ServerState.Available: false`) — Cashalot регистрирует в своей офлайн-сессии | Ничего: доставит сам и вернёт кассу в онлайн на первой команде после восстановления; проверять «Потребують уваги» |
| При `Available: false` продажи отказывают, а не идут офлайн | ПРРО зарегистрирован без разрешения офлайна в форме 1-ПРРО | Ждать восстановления ФСКО; на будущее — перерегистрировать с офлайном (п. 1) |
| Тумблер «Реєструвати чеки в ПРРО» задизейблен | Провайдер не выбран или нет адаптера | П. 3, обновить деплой |
| Пункт «Фіскалізація» не появился после логина | Модуль не подключён (п. 4), провайдер не совпал с id модуля, или надо перезайти | Проверить «Онлайн-модулі», перелогиниться |
| Продажа падает 503 `fiscal_unavailable` | Нет связи с Cashalot или зміна не открылась | `/fiscal` → открыть зміну, `support_code` в ответе |

## На заметку про версии модуля

Как у Checkbox: URL в `pos_stores.module_remotes` — **конкретная версия**.
Новый релиз (шаг 2) нужно **заново вписать** в каждый магазин — через
супер-админку `/super` ([POS_SUPER_ADMIN.md](../../POS_SUPER_ADMIN.md)), панель
«Перенацілити модуль», с проверкой подписи манифеста.
