# Checkbox API — Режим роботи каси (офлайн/онлайн)

Джерело: https://wiki.checkbox.ua/api/cash-register, знято 2026-09-10 (16 PDF з
розкритими вкладками «Опис / Приклад запиту / Відповідь сервера / Опис
параметрів»). Текст зведений і дедуплікований; формулювання Checkbox збережено.
Для полів запитів/відповідей див. також `openapi-2.106.4.json` (схеми
`GoOfflinePayload`, `DetailedOfflineFiscalCodeModel`, `OfflineCodesCountSchema`,
`DetailedCashRegisterModel`).

> ⚠ Максимальний режим роботи в офлайн режимі — **36 годин**.

## 1. Перевірка інформації про касу

`GET /api/v1/cash-registers/{cash_register_id}`

Щоб отримати UUID каси — `GET /api/v1/cash-registers`. Параметр `offline_mode`
повідомляє поточний статус: `false` — онлайн, `true` — офлайн.

Заголовки: `X-Client-Name`, `X-Client-Version` (обов'язково), `Authorization:
Bearer <token>`. Тіло порожнє.

```json
{
  "id": "c13876dd-e51e-433f-a61c-f2c426311111",
  "fiscal_number": "TEST511111",
  "active": true,
  "created_at": "2022-07-26T19:54:09+00:00",
  "updated_at": "2023-11-10T22:55:07+00:00",
  "number": "1",
  "shift": null,
  "offline_mode": true,
  "stay_offline": true,
  "branch": null,
  "address": "УКРАЇНА, М.КИЇВ ГОЛОСІЇВСЬКИЙ Р-Н, Тестова, 41а",
  "type": 0
}
```

| Поле | Значення |
|---|---|
| `id` | UUID каси |
| `fiscal_number` | фіскальний номер каси (ФН ПРРО) |
| `active` | `false` для деактивованих у Checkbox кас |
| `created_at`, `updated_at` | ISO 8601 `YYYY-MM-DDThh:mm:ss.ssssss±hh:mm` |
| `number` | порядковий номер каси |
| `shift` | блок зміни або `null`, якщо зміну не відкрито |
| `offline_mode` | `true` — каса в офлайні |
| `stay_offline` | `true` — перехід в офлайн виконано **клієнтом** (`go-offline`), а не автоматичним переходом при мовчанні ДПС |
| `branch` | торгова точка; для тестової каси завжди `null` |
| `address` | адреса торгової точки |

## 2. Офлайн-коди

### 2.1 Отримання нових кодів з ДПС

`GET /api/v1/cash-registers/ask-offline-codes?count=<n>&sync=<true|false>`
Заголовки: + `X-License-Key` (обов'язково).

- Працює **тільки коли каса в ОНЛАЙН режимі**. Після виконання номери
  зберігаються на сервері Checkbox і стають доступними через `get-offline-codes`.
- `sync=false` (async) — одразу повертає `"status": "OK"` (або `"ERROR"` на
  етапі формування запиту) незалежно від того, чи дійшов запит до ДПС: «ОК»
  означає лише успішну відправку. `sync=true` — обробляє повністю: `"DONE"`,
  якщо запит дійшов до ДПС, `"TIMEOUT"`, якщо ДПС не відповіла вчасно,
  `"ERROR"` — помилка. Поле `error` — текст помилки.
- **Максимальна кількість кодів, яку повертає ДПС — 5000.**
- Номер перестає повертатися ДПС («використаний») **лише після відправки до ДПС
  транзакції з цим номером**. До того ДПС повертає той самий номер при кожному
  виклику: перший запит на 100 → 100 нових; наступний на 200 → ті самі 100 + ще
  100 наступних.
- ⚠ **Після запиту офлайн-кодів будь-які офлайн-транзакції (зміни, чеки,
  офлайн-переходи) можна відправляти тільки з `fiscal_date` БІЛЬШОЮ АБО РІВНОЮ
  даті/часу виконання `ask-offline-codes`.**

Приклад: `GET …/ask-offline-codes?count=2000&sync=true` → `{"status": "OK"}`.

### 2.2 Отримання списку невикористаних кодів

`GET /api/v1/cash-registers/get-offline-codes?count=<n>`
Заголовки: + `X-License-Key`.

- Віддає невикористані на цей момент коди з сервера Checkbox **навіть якщо ДПС
  недоступна** (за умови, що раніше був `ask-offline-codes`). Саме ним варто
  користуватись, поки запас не впаде до критичного (напр. 500).
- **Будь-який код можна використати лише 1 раз** — на транзакцію
  відкриття/закриття зміни, офлайн-перехід або чек.
- ⚠ **Checkbox сам автоматично переходить в офлайн при тайм-ауті ДПС:** сервер
  створює транзакцію офлайн-переходу і починає підставляти доступні офлайн-коди
  в чеки, **навіть якщо ви шлете їх як онлайнові.** Тому перед відправкою
  офлайн-чеків слід синхронізувати пул кодів, інакше — помилка
  `Offline code '<код>' was used before!`.
- Якщо `count` перевищує наявну кількість — повертає скільки є; якщо кодів
  немає — порожній масив.

```json
[
  { "fiscal_code": "TEST-iA5fmb", "serial_id": 1, "cash_register_id": "c13876dd-…", "created_at": "2023-11-08T12:25:21.586071+00:00" },
  { "fiscal_code": "TEST-aQ-V-c", "serial_id": 2, "cash_register_id": "c13876dd-…", "created_at": "2023-11-08T12:25:21.586073+00:00" },
  { "fiscal_code": "TEST-WzSbIz", "serial_id": 3, "cash_register_id": "c13876dd-…", "created_at": "2023-11-08T12:25:21.586073+00:00" }
]
```

`serial_id` — порядковий номер коду, `created_at` — дата створення коду.

## 3. Перехід в онлайн

`POST /api/v1/cash-registers/go-online` (тіло порожнє; + `X-License-Key`).
Відповідь: `{"status": "ok"}`.

- Сама команда **не означає**, що каса одразу в онлайні: якщо в черзі багато
  офлайн-чеків, одного запиту може бути недостатньо. Через хвилину перевірити
  `GET /cash-registers/{id}` (`offline_mode`); якщо все ще `true` — надіслати
  `go-online` ще раз і знову перевірити через хвилину, у циклі. Після виходу в
  онлайн — **зупинити** повторні `go-online`.
- **Rate limit: не більше 1 запиту раз на 2 хвилини, на кожну касу окремо** (не
  на IP). При систематичному порушенні Checkbox зв'язується за контактами
  організації.
- Якщо `go-online` надіслано більше разів, ніж є невідправлених офлайн
  транзакцій, або каса довго не виходить в онлайн — звернутись у підтримку.

## 4. Перехід в офлайн

`POST /api/v1/cash-registers/go-offline` (+ `X-License-Key`, `Content-Type:
application/json`). Для переходу достатньо **1 успішного** запиту.

```json
{ "go_offline_date": "2023-11-29T06:14:20+0200", "fiscal_code": "TEST-aQ-V-c" }
```
Відповідь: `{ "status": "ok", "id": "4722e600-905f-4a89-9d71-801698125664" }` —
`id` — UUID транзакції.

- `go_offline_date` — фіскальна дата ISO 8601; це дата/час, з якою перехід
  буде зареєстровано в ДПС. Не вказано → поточний час.
- `fiscal_code` — **раніше не використаний** офлайн-код. Не вказано → сервер
  підставить вільний код сам; спроба потім відправити чек з цим (автоматично
  використаним) кодом дасть помилку. Отже тіло може бути й порожнім.
- ⚠ **Перейти в офлайн можна лише з `go_offline_date` БІЛЬШОЮ АБО РІВНОЮ
  даті/часу останньої успішно доставленої в ДПС транзакції** (чеку, відкриття/
  закриття зміни, переходу в онлайн). **Невірна дата призводить до застрягання
  каси в офлайні та ПОЛОМКИ КАСИ.**

## Наслідки для нашого дизайну (POS_FISCAL_OFFLINE.md)

1. Порядок часу — жорсткий: `ask-offline-codes` ≤ будь-яка офлайн-транзакція;
   `go_offline_date` ≥ остання доставлена транзакція. Реплей офлайн-сесії, що
   перекривається з онлайн-чеками того ж регістратора, **зламає касу** — поки
   каса тримає офлайн-оренду, інші продажі цього магазину онлайн проводити не
   можна (одна каса на регістратор у v1).
2. Checkbox сам іде в офлайн при мовчанні ДПС і витрачає коди з пулу —
   наш пул треба **пересинхронізувати** перед реплеєм, а «used before» вважати
   очікуваною помилкою: взяти наступний код.
3. `go-online` — асинхронний, з опитуванням статусу раз на хвилину і лімітом
   1/2 хв на касу; це робота крону, не запиту.
4. ДПС видає до 5000 кодів; серверний пул + оренди касам мають вкладатися.
