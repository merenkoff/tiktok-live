# ДПС: API Фіскального Сервера — что из него важно для нас

`fiscal-server-api.md` — полный снимок официального описания API, по которому
**ПРРО** (у нас — Checkbox, не мы) разговаривает с Фискальным Сервером ДПС.
Снят 2026-09-12, чтобы перестать спорить о реквизитах офлайн-чека по
пересказам.

Четыре факта, которые правят дизайн офлайн-режима
([POS_FISCAL_OFFLINE.md](../POS_FISCAL_OFFLINE.md)):

1. **Онлайн-номер чека назначает Сервер.** «Фіскальна нумерація документів
   ведеться Сервером» — поэтому на онлайн-чеке нет никаких контрольных
   чисел, только номер, дата/время, сумма, ФН ПРРО. Реальный чек магазина
   выглядит именно так.
2. **Офлайн-номер чека собирает сам ПРРО**, и контрольное число — его
   хвост: `<ідентифікатор офлайн сесії>.<локальний номер в сесії>.<контрольне
   число>`, например `82563.25.6127`. Это не отдельный реквизит рядом с
   номером, а часть самого номера офлайн-документа.
3. **Контрольное число нельзя посчитать снаружи ПРРО.** Это CRC32 от строки
   `«секретне число»,дата,час,локальний номер,ФН ПРРО,локальний номер
   реєстратора,сума,геш попереднього документа` → четыре младшие цифры.
   «Секретне число» (`OfflineSeed`) Сервер выдаёт ПРРО вместе с номером
   офлайн-сессии при открытии смены и обновляет после каждого офлайн-пакета;
   геш предыдущего документа — SHA-256 подписанного XML предыдущего
   документа сессии. Ни того, ни другого у интегратора над облачным API
   Checkbox нет и быть не может.
4. **Про бумажный чек здесь ничего нет.** Документ описывает обмен
   ПРРО ↔ Сервер; форму и содержание печатного чека регулирует Положення
   (наказ Мінфіну № 13). Вопрос «можно ли отдать покупателю офлайн-чек без
   контрольного числа» этим документом не закрывается.

Что из этого следует для нас — в
[POS_FISCAL_OFFLINE.md → «Открытые вопросы»](../POS_FISCAL_OFFLINE.md).
