# Реальні пари запит/відповідь Cashalot WEB API

Знімає `npm run fiscal:sandbox:cashalot` (`src/pos/fiscal/providers/cashalot/sandbox.ts`)
на справжньому ПРРО в тестовому режимі — окремої пісочниці в Cashalot немає
(відповідь розробки 1, `TechDocs/prro/cashalot/sources/support-answers.md`).
Кожен прогін лишає теку `runs/<мітка часу>/`: по файлу на крок — запит із
замаскованими `KeyGuid`/`KeyPin` поруч із відповіддю, бо розробка Cashalot
розбирає помилки саме за ними (відповідь 6), — а також `console.log` і
`run.json` з рядками `ANSWER …`. Справжніх ключів тут бути не може; перед
комітом прогону переглянути файли очима.

Що перевіряють проби — `TechDocs/prro/cashalot/POS_FISCAL_CASHALOT.md` §4.5.
Прапорці:

```bash
npm run fiscal:sandbox:cashalot                 # лише читання: проби 1, 7
npm run fiscal:sandbox:cashalot -- --shift      # + 2: відкрити ТЕСТОВУ зміну
npm run fiscal:sandbox:cashalot -- --sell       # + 3, 4, 5, 8 (потрібна відкрита тестова зміна)
npm run fiscal:sandbox:cashalot -- --return     # + 6: повернення, внесення/видача, X, Z, повторне закриття
npm run fiscal:sandbox:cashalot -- --all        # усе по черзі
```

Скрипт нічого не пише, поки на ПРРО відкрита фіскальна зміна (вихід 3), а
кожен документ і зміна йдуть із `TESTING`.

## Проба 9 — виклик із продакшн-мережі

Розробка попередила, що IP із країн під обмеженнями можуть блокуватися
(відповідь 4), а проби вище йдуть із машини розробника. Один виклик із
контейнера API на Railway (`railway ssh`, див. пам'ять про доступ до шелу):

```bash
node -e "fetch('https://fsapi.cashalot.org.ua/',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({Command:'ServerState'})}).then(async r=>console.log(r.status,await r.text()))"
```

Очікується `200` і `{"Available":true,…}`; будь-що інше — записати сюди.

**Прогін 2026-10-27, 12:13–12:15 UTC**, без ключів: сервіс `tiktok-live`,
регіон Railway EU West, Node 20.20.2. Для порівняння той самий запит пішов із
машини розробника, а також `ServerState` до самого сервера ДПС (адреса з
`TechDocs/prro/dps/fiscal-server-api.md`, без автентифікації):

| Звідки | Куди | Відповідь |
|---|---|---|
| контейнер API на Railway | `fsapi.cashalot.org.ua`, `ServerState` | двічі `200`, за 215 і 240 мс: `{"Available":false,"Version":"2.1.0.8034","ErrorCode":"Ok","ErrorMessage":null}` |
| машина розробника | те саме | `200` за 219 мс, та сама відповідь |
| контейнер API на Railway | `fs.tax.gov.ua:8643/fs/cmd`, `ServerState` | з'єднання не встановилося за 10 с (`UND_ERR_CONNECT_TIMEOUT`) |
| машина розробника | те саме | те саме |

Висновок — знахідка 1.

## Знахідки

Формат — як у `../checkbox/README.md`: пронумеровані знахідки, що змінюють
дизайн адаптера. Решта проб — після CA0 (ключі в `.env`).

1. **Railway до Cashalot доходить, гео-обмеження немає** (проба 9,
   2026-10-27). Контейнер API отримує ту саму відповідь, що й машина
   розробника, приблизно за 0,2 с, тож окремий вихід в інтернет через Україну
   облачному WEB API не потрібен.
   - `Available: false` прийшов з обох місць однаково, отже від IP не
     залежить. За специфікацією це ознака доступності ФСКО в режимі онлайн:
     у цю хвилину Cashalot не бачив сервера ДПС. Чому — не встановлено. Того
     ж ранку ДПС повідомила, що технічні роботи завершено
     ([новина](https://tax.gov.ua/media-tsentr/novini/1062537.html), знайдена
     пошуком; `tax.gov.ua` звідси відповідає 403). Спитати стан самого ПРРО
     (`TransactionsRegistrarState`) без ключів не можна. Повторити
     `ServerState` разом із пробою 1 після CA0.
   - Адаптер `Available` не читає. Якщо Cashalot не бачить ДПС, чек
     повертається з `Offline: true` і стає `provider_offline`; це покрито
     тестами CA5.
   - До сервера ДПС напряму не дістався ні Railway, ні машина розробника
     (тайм-аут з'єднання). Облачному WEB API це байдуже: з ДПС говорить
     Cashalot. Але FS API, розгорнутий у нас (єдиний шлях до каси без
     інтернету, CA8), мусить ходити до `fs.tax.gov.ua` сам. Якщо це не
     разовий збій, на Railway EU West він не працюватиме. **Перевірено ще раз
     27.10 о 21:24 UTC**: DNS дає 89.231.20.215, TCP на `8643` і `8609` не
     відкривається за 10 с ні з Railway, ні звідси, Cashalot у ті ж секунди
     відповідає за 0,2–0,4 с. Того ж вечора розробка Cashalot відповіла, що
     у ДПС **загальний збій ФСКО** (`TechDocs/prro/cashalot/sources/
     support-answers.md`, 15–16) — тож тайм-аути ним і пояснюються, а чи
     впускає ФСКО довільні адреси, лишається відкритим: повторити пробу,
     коли `ServerState` поверне `Available: true`. **Повторено 1.11.2026 при
     `Available: true`**: `8643` і `8609` відповідають `200
     {"UID":null,"Timestamp":…}` за 49–85 мс і з Railway, і звідси — allowlist
     немає, питання закрите. Висновок — у `TechDocs/prro/POS_FISCAL_OFFLINE.md`.
   - `Available: false` в обох пробах (12:15 і 21:24 UTC того ж дня) — той самий збій ДПС, не стан нашої
     сесії; документи в цей час реєструються в офлайн-сесії Cashalot, якщо
     ПРРО дозволено офлайн формою 1-ПРРО.

2. **`LicenseViolation` — ліцензію на ПРРО треба завантажити в кабінеті**
   (проба 1, 2026-11-01, перший виклик із ключами). `ServerState` → `Available:
   true`, а `TransactionsRegistrarState` → HTTP 200, `ErrorCode:
   LicenseViolation`, «Неліцензійне використання програмного забезпечення -
   Відсутня ліцензія на ПРРО з фіскальним номером '<ФН>' для платника податків
   '<код>'». Ключі й ФН Cashalot прийняв (інакше була б
   `OperatorAccessToTransactionsRegistrarNotGranted`); не вистачає кроку зі
   спеки «в списку кас завантажити та зберегти ліцензії для ПРРО». Адаптер
   відповідав на це ім'я `unknown` — тепер `auth_rejected` (`dps/errors.ts`),
   бо документа немає й чинить це власник у кабінеті. Тека прогону в git не
   покладена: текст помилки містить РНОКПП власника.
