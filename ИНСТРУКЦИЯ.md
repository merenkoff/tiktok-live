# Инструкция: настройка и работа с эфирами

Коротко для тех, кто будет включать систему и вести продажи в TikTok LIVE. Без технических терминов.

## Зачем это нужно

Пока вы ведёте эфир, зрители пишут в комментариях артикул и размер (например, модель и размер одежды). Система **фиксирует заявку** и на короткое время **бронирует** позицию за этим человеком. Дальше покупатель **оформляет заказ в Telegram**: имя, телефон, город, отделение. **Админы** получают уведомление в ваш служебный чат или канал в Telegram. Если вы отправляете посылки через Новую Почту и подключили ключ в настройках, позже можно автоматизировать накладные и трек-номер — это необязательно для старта.

## Что подготовить заранее

- Аккаунт TikTok с возможностью выходить в **LIVE** (эфир).
- **Telegram-бот** для заказов (его создаёт @BotFather, вы получаете токен).
- **Канал или группа** в Telegram, куда бот сможет слать уведомления администраторам (нужен числовой идентификатор чата — его обычно подсказывает разработчик или инструкция по настройке).
- Компьютер или сервер, на котором **постоянно запущена** эта программа, пока идёт приём заказов с эфира (или облако с тем же смыслом).

## Один раз: настройка

1. В папке проекта скопируйте файл примера настроек в рабочий файл с именем `.env` (как это сделать, покажет разработчик или раздел «быстрый старт» в основной документации).
2. В `.env` **обязательно** укажите:
   - ник TikTok, с которого идёт эфир;
   - токен бота;
   - идентификатор канала или чата для уведомлений админам.
3. Поля про **базу данных** и **Redis** не меняйте без указания специалиста: оставьте как в файле-примере `.env.example`, чтобы программа находила ту же базу, что поднимается через Docker в этом проекте.
4. Ключ **Новой Почты** и название отправителя заполняйте только если уже пользуетесь интеграцией с доставкой — иначе можно оставить заглушки из примера.

## Как запустить перед работой

**Вариант 1 — всё одной командой (удобно, если настроен Docker):**

```bash
docker compose up -d
```

Подождите около минуты, пока сервисы поднимутся. Смотреть, что пишет программа, можно так:

```bash
docker compose logs -f app
```

**Вариант 2 — программа на вашем компьютере, а база данных в Docker (частый случай для разработки):**

Сначала поднимите только базу и вспомогательные сервисы:

```bash
npm run docker:deps
```

Один раз установите зависимости: `npm install`.  
Для обычной работы с автоперезапуском при правках: `npm run dev`.  
Для запуска «как в продакшене» после сборки: `npm run build`, затем `npm start`.

Настройки базы в `.env` должны **совпадать** с тем, что в `.env.example`, если вы не получали отдельных указаний.

## Во время эфира

1. Запустите систему **до** или **в начале** эфира и не выключайте, пока принимаете заказы.
2. Договоритесь со зрителями, **как писать комментарии**, например: `A12 92` (модель и размер) или короткая фраза с моделью на русском — как договорились в магазине.
3. После комментария система создаёт **бронь на несколько минут** (обычно пять). За это время покупатель должен зайти в **вашего бота в Telegram** и пройти шаги: подтверждение резерва, имя, телефон, город, отделение (кнопками или текстом — как настроен бот).
4. Озвучьте в эфире **имя бота или ссылку** на него, чтобы люди не искали его сами.
5. В **админский чат** придёт сообщение о новом заказе. Дальше вы работаете по своим правилам магазина: проверка оплаты, сбор, отправка. Если подключена Новая Почта, отдельные команды бота для трек-номера настраивает тот, кто ведёт техническую часть.

## Если что-то не работает

Проверьте по порядку:

- Команда с базой выполнена и контейнеры с базой **запущены** (или выбран полный запуск через Docker).
- Файл `.env` сохранён и в нём **нет пустых** обязательных полей (TikTok, токен бота, чат админов).
- Эфир в TikTok **реально идёт** с того аккаунта, ник которого указан в настройках.
- Бот в Telegram **не заблокирован** и добавлен в админский канал/группу с правами писать сообщения, если это требуется.

Посмотреть текст ошибок можно в логах приложения, например:

```bash
docker compose logs -f app
```

Если запуск без Docker — смотрите вывод в том же окне терминала, где вы запустили `npm run dev` или `npm start`.

Дальше обращайтесь к человеку, который настраивал сервер или репозиторий: по логам быстрее понять причину.
